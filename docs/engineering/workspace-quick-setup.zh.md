# 工作区一键初始化

入口：设置 → 一键初始化（`/{workspaceSlug}/settings?tab=setup`）。

同一页面选择设计小队、确认人和开发小队，默认配置工作区流程，也可切换为指定项目，连同流程模板、GitLab、CI、KB 统一提交。不需要的配置可以关闭；关闭仅表示本次不配置，不会删除已有配置。

## 配置落点

| 页面配置 | 复用接口 | 原有管理入口 |
| --- | --- | --- |
| 小队模板 | `/api/process-templates/{id}/apply` | 设置 → 流程模板 |
| 设计确认与小队交接 | `/api/issue-workflows` | 设置 → 工作流 |
| 创建项目或绑定流程 | `/api/projects`、`/api/projects/{id}/workflow` | 项目 → 工作流 |
| GitLab 连接 | `/api/workspaces/{id}/vcs/connections` | 设置 → 代码 |
| CI 默认规则 | `/api/workspaces/{id}/vcs/delivery-defaults` | 设置 → 代码 |
| KB 地址、令牌 | `/api/system/settings` | 系统管理 → 系统设置 |

初始化只组织现有 API，不改变原有功能页面、权限或执行逻辑。Web 和桌面使用同一个设置组件。

## 设计到开发

“设计到开发”默认开启，确认人默认为当前成员。两个小队分别支持选择已有小队，或选择模板中的小队；所需模板会自动勾选，安装后使用服务端返回的确切小队 ID。

一次保存将以下流程设为工作区默认，不要求创建或关联项目。未关联项目的任务，以及未指定独立流程的项目任务，都会使用该流程；已指定独立流程的项目不受影响。此处的默认是工作区级别，不会影响其他工作区或系统管理中的客户项目：

1. 任务进入待办，触发产品设计小队。
2. 设计小队把设计产物与验收标准留在同一条任务中，再将状态移至“设计确认”。
3. 此阶段指派给确认人，不启动开发小队。确认人通过后将状态改为“进行中”，才触发开发小队；需修改则退回待办。
4. 开发小队直接沿用已确认的设计和任务上下文，不重新经过整体智能体规划。开发完成后进入“待评审”，由确认人验收。

初始化不会启动任何已有任务、移动已有任务的状态，也不会因为某次运行结束就自动跨过人工确认。重新初始化工作区默认流程时，以当前选择的小队、确认人和阶段配置更新默认流程；配置相同则跳过保存。

需要项目单独配置时，将“流程范围”切换为“指定项目”。可选择已有项目，或创建新项目并绑定独立流程。项目模式重复提交会复用同名且阶段配置一致的流程；若流程已被手动修改或由其他项目使用，拒绝覆盖。若项目中已有任务使用新流程之外的状态，保留新建流程但不切换项目，需到工作流设置中人工确认状态映射后再切换。项目要恢复继承时，在项目工作流设置中选择工作区默认流程。

## 行为边界

- 工作区 owner/admin 可以初始化；KB 仍需系统管理员权限，并会影响所有工作区。
- 安装小队模板需要在线运行时，绑定逻辑沿用现有模板接口。
- 已安装模板不重复应用，也不自动升级，保留用户调整。
- 已有 GitLab 连接不会重连，避免轮换 webhook 密钥；替换令牌仍使用原管理入口。
- CI 开启默认跟踪和仓库自动发现，不需要逐项目配置 ID，不限制固定部署主机；其他现有 CI 规则保留。
- CI 的部署日志地址标记可在初始化页调整。此操作配置跟踪规则，不会替用户新增 `.gitlab-ci.yml`、触发构建或更改 GitLab runner。
- KB 令牌留空保留已有值；切换 KB 服务地址时必须提供对应令牌。
- 提交前读取并校验所选配置；写入不跨接口事务化。失败时保留已成功配置，再次提交会重新读取模板和连接状态，跳过已安装模板、已连接 GitLab。
- 密钥仅用于本次请求，不写入浏览器持久化存储，保存成功后清空输入；错误提示不回显上游原始错误或令牌。

本机完整环境启动仍使用 `make up`（Windows 可调用 `scripts/dev-env.sh`），需要可用的 PostgreSQL。
